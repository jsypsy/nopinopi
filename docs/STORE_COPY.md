# 앱인토스 콘솔 앱 정보 — 입력 문안

콘솔 > 앱 정보에 그대로 들어가는 문안. 이미지는 `assets/store/` 9장, 제작은 `tools/store-compose.html`.
보낼 JSON은 `docs/store-payload.json`(업로드된 이미지 주소까지 박혀 있다).
⚠️ **MCP 경로는 등급 전에는 못 쓴다** — 아래 "등록 상태" 절.

> ⚠️ **게임 화면에 실제로 찍히는 문자열과 다른 이름을 쓰지 않는다.**
> 화면 문구가 기준이다: `탭해서 시작` · `오늘의 탑, 몇 층까지?` · `탭하면 블록이 떨어져요 · 딱 맞추면 안 잘려요` ·
> `딱!` · `폭 회복!` · `끝` · `이번 탑` · `광고 보고 이어하기` · `다시 하기` · `오늘 n층 · 역대 n층` · `9월 4일의 탑`.
> GRAC 제출 문서(`grac-제출/`)도 같은 표기다 — 갈리면 그 자체가 지적 사유가 된다.

여기서는 처음부터 같게 둔다. 증명서가 나오면 제명을 다시 대조한다.

## 부제 (필수, 20자)

```
오늘의 탑 몇 층까지?
```

12자. 시작 화면 문구(`오늘의 탑, 몇 층까지?`)에서 **쉼표만 뺐다** — 콘솔 부제 칸은
`특수문자는 :, ·, ? 만 사용할 수 있어요`로 쉼표를 거부한다(2026-09-04 입력 중 확인).
검수자가 화면과 1:1로 대조할 수 있고, 이 앱의 리텐션 장치(일일 시드 — 오늘의 탑)가 한 줄에 들어간다.

**대안**

| 문안 | 자수 | 성격 |
| --- | --- | --- |
| 탭 한 번으로 쌓는 탑 | 12 | 조작을 앞세움 |
| 오늘은 모두 같은 탑을 쌓아요 | 15 | 일일 시드를 앞세움 |
| 딱 맞추면 안 잘려요 | 11 | 핵심 규칙 |

## 상세 설명 (필수, 500자 이내)

466자. 입력란 안내가 "무엇을 보고, 어떤 버튼을 누르고, 무엇을 경험하는지"라
**실제 화면 문구를 그대로** 넣었다. 원문은 `docs/store-payload.json`의 `detailDescription`.

```
「높이높이」는 화면을 탭하는 것만으로 쌓아 올리는 원버튼 게임입니다.

시작 화면에서 [탭해서 시작]을 누르면 바로 시작합니다. 화면 위쪽에서 블록이 좌우로 왕복하고, 화면 아무 곳이나 탭하면 그 자리에서 블록이 떨어져 아래 블록 위에 얹힙니다. 어긋난 만큼 잘려 나가 폭이 줄고, 빗나가면 그 자리에서 끝납니다.

딱 맞추면 잘리지 않고 「딱!」이 뜹니다. 세 번 연속 성공하면 「폭 회복!」과 함께 줄어든 폭이 조금 되돌아옵니다. 실수를 만회하는 유일한 길입니다. 쌓아 올린 층수가 점수이고, 높이 올라갈수록 블록이 빨라지며 하늘이 낮에서 노을, 밤, 우주로 바뀝니다.

같은 날에는 모두가 같은 탑을 쌓습니다. 블록의 속도와 첫 출발 방향이 그날의 날짜로 정해지기 때문입니다. 오늘의 최고 기록과 역대 최고 기록이 함께 표시되고, 게임이 끝나면 [광고 보고 이어하기]로 그 자리에서 이어 가거나 [다시 하기]로 새로 시작합니다.
```

## 카테고리

**게임 > 클래식** (`categoryIds: [3856]`). 게임 그룹에는 서브카테고리가 없어 `subCategoryIds`는 보내지 않는다.

콘솔에 「아케이드」 칸이 없다(액션·RPG·전략·어드벤처·퍼즐·시뮬레이션·레이싱·퀴즈·카드·보드·클래식·음악·스포츠·인디).
GRAC 신청 장르는 "아케이드(원버튼 탑 쌓기)"이고, 탑 쌓기는 조작 하나짜리 고전 아케이드 계열이라 **클래식**으로 간다.
형제 앱(슈팅스타·날아날아)이 액션에 몰려 있어 같은 칸에서 서로 밀어내지 않는 이점도 있다.
대안은 액션(3836) — 노출이 아쉬우면 그쪽으로 옮긴다.

## 앱 검색 키워드 (필수, 최대 10개 · 한글/영문/숫자/공백만)

```
높이높이, 탑쌓기, 블록쌓기, 원버튼게임, 한손게임, 미니게임, 캐주얼게임, 아케이드, 하이스코어, 오늘의탑
```

- 앞쪽 3~4개가 가장 중요하다 (앱 이름 + 소재 + 조작).

- 특수문자가 들어가면 등록이 거부된다. 쉼표는 구분용이고 실제로는 배열로 보낸다.

### 다시 만드는 방법

로고·썸네일은 `tools/store-compose.html`(캔버스를 규격 크기 그대로 그린다), 세로 스크린샷은
`tools/frame.html`의 iframe을 **318×524 CSS px**로 줄여 게임을 그 크기로 직접 렌더한 뒤 캔버스를 그대로 읽는다
(dpr 2 → 캔버스 636×1048). **콘솔은 1px만 달라도 업로드를 거부하므로 축소·크롭하지 않는다.**

```
node tools/shot-receiver.mjs assets/store 5300      # PNG 수신구
npx vite --port 5178 --strictPort --host 127.0.0.1  # 개발 서버
```

크롬 MCP로 `tools/store-compose.html?kind=logo|logo-dark|thumb`를 열고 `window.__send('파일명')`,
게임 화면은 `tools/frame.html`에서 iframe을 318×524로 줄이고 `__nopi` 훅으로 장면을 만든 뒤
캔버스 `toDataURL`을 수신구로 보낸다. 배경 탭의 rAF·타이머 조임 함정은 `grac-제출/README.md`와 같다
(rAF를 끄고 `stepOnce`로만 그린다 · 팝업 900ms · 사망 카드는 호출을 두 번으로 나눈다).

## 등록 상태 — 1·2단계 임시저장 **완료** (2026-09-04)

**콘솔 웹에서 1단계(기본 정보)·2단계(카테고리 및 노출)를 채우고 [임시저장]으로 넣었다.**
앱 정보 화면에 부제·카테고리(게임>클래식)·검색 키워드 10개·로고·썸네일·고객문의 이메일이 모두 찍혀 있다.
스크린샷 6장과 리더보드 점수 단위(`층`/`floors`, 높은 점수부터)도 2단계에 들어갔다.
남은 것은 3단계(게임 등급분류)뿐이고, 거기서 [검토 요청하기]를 누르면 등록이 끝난다.

### ⛔ MCP로는 이 상태를 만들 수 없다 (날아날아에서 두 번 확인)

`miniapp_update_basic_info`는 **전체 페이로드 + 검토 요청이 한 몸**이라 등급 칸이 비면
**저장 없이 통째로 거부**된다.

| 보낸 것 | 응답 |
| --- | --- |
| `gameInfo`에 `gameRating` 없이 | `스토어 링크 또는 게임물 등급분류증명서를 등록해주세요.` |
| `gameInfo` 자체를 빼고 | `게임 정보가 존재하지 않아요.` |

게임 카테고리 → `gameInfo` 필수 → 증명서 필수로 물려 있어 MCP에는 빠져나갈 구멍이 없다.
**콘솔 웹의 단계별 [임시저장]이 유일한 길이다.**

### 3단계에서 요구하는 것 (전부 GRAC 결정 뒤)

등급분류번호 · 분류일 · 게임물제작업자 신고번호 · 이용등급 · 내용정보 · **대표자 인감 또는 사인 이미지** ·
**게임 주요화면 2쌍**(자체등급분류 게임물 화면 + 앱인토스 게임물 화면). 그리고 확약 5개 체크 → [검토 요청하기].

> 인감·사인 이미지는 문서에 없던 요구다. 등급 수령 시점에 파일부터 찾아 둘 것.

**결정이 나면**: `docs/store-payload.json`의 `_등급_수령후_추가` 자리를 채워
(`ageRating: ALL` · `bizName: 토니소프트` · `ratingNumber` · `contentRatings: ["NONE"]`)
`miniapp_update_basic_info` 한 번이면 끝난다. 이미지 9장은 이미 올라가 있어 다시 만들 필요 없다.

⚠️ **증명서 PDF는 MCP로 못 올린다.** `image_upload_url`은 png·jpg만 발급한다.
콘솔 웹 게임 등급분류 화면에서 PDF를 먼저 올리고, 저장된 키를 `miniapp_get`으로 읽어 페이로드에 넣는다.
